# Captain Scenario — Usage & installation

## When to use

Use when the customer has already purchased but cannot get it working: how to install, what activation means, a QR code that will not scan, an accidentally deleted eSIM, moving to a new phone, no internet after arriving at the destination, weak signal or slow speed, or usage figures that look wrong.

## Handling rules

- Before telling the customer when to install, check whether the plan activates on installation, on first connection to a supported network, or on another trigger.
- Check the activation rule before advising. If the plan activates on installation, suggest installing close to departure. If it activates on first connection at the destination, installing before departure is usually fine. Do not apply one plan type's rule to another. Keep data roaming off before arrival and enable it at the destination as the plan requires. If the customer wants to buy now and activate much later, always state that plan's own installation deadline and validity rule — never answer that it can be activated at any future time.
- Treat those paths as a hint, not as a guaranteed answer for the customer's device. Do not pretend to know the exact menu name on an unknown device. If the path differs, ask for the operating system, device model, sales region or regional version, carrier-lock status, and the exact screen text. When the device shows a message such as "carrier lock", "eSIM not supported", or "cannot add mobile plan", use the exact message to separate a carrier lock from a regional-version or policy restriction; if it cannot be separated, escalate.
- Do not promise automatic activation solely because data roaming is enabled.
- Check the order status, installation state, activation rule, current location, selected data line, roaming setting, and the exact device message. Escalate if the device and order states conflict, or if the status does not progress after the relevant conditions are met.
- Ask what appears in the device SIM list. Do not tell the customer to scan the QR code again if an eSIM profile is already present.
- Record the exact error and the current installation state. QR reissue, installation reset, or device unbinding requires current order evidence or staff approval.
- Never advise the customer to delete an existing eSIM as a troubleshooting step unless reinstallation eligibility has already been confirmed. Escalate when a QR reset, reissue, or backend action is required.
- Do not promise that the eSIM can or cannot be transferred without current product or supplier evidence.
- Verify the order and coverage before troubleshooting the device. Give one useful check at a time and ask for the result. Only provide an APN when it comes from current product or order data; never guess an APN, an operator, or a coverage area. Tell the customer what they should expect to see at each step before moving on.
- Confirm the plan's coverage for the customer's current country before treating this as a device or network fault. Do not promise that the existing plan works outside its coverage. If the customer holds several plans, remember that each plan has its own installation deadline, activation rule, and validity period, so one plan's state must not be used to describe another.
- Check plan limits, fair-use or throttling status, remaining data, supported operators, and local coverage. Do not promise a particular speed. Escalate with a redacted settings screenshot and a summary of the checks already completed when a network-side issue is suspected.
- Do not assume that zero displayed usage means no data was consumed. State when the tool data is delayed or unavailable, and name the field that is missing.
